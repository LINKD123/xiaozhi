# 小智整条链路：从听到声音到大模型（以及开车）

这份文档整理「语音如何一步步到达大模型、大模型结果如何回到板子」以及各角色的输入输出。目的是对照源码把整条链看懂，而不是当成刷机手册。

相关工程：

- 设备固件：[78/xiaozhi-esp32](https://github.com/78/xiaozhi-esp32)
- WebSocket：[文档](https://xiaozhi.dev/en/docs/development/websocket/)
- MCP：[mcp-protocol.md](https://github.com/78/xiaozhi-esp32/blob/main/docs/mcp-protocol.md)、[mcp-usage_zh.md](https://github.com/78/xiaozhi-esp32/blob/main/docs/mcp-usage_zh.md)
- 开源后端（自建时）：[xinnan-tech/xiaozhi-esp32-server](https://github.com/xinnan-tech/xiaozhi-esp32-server)

---

## 1. 先记住三句话

1. **小智不是大模型。** 它是 ESP32 固件 + 云端/自建编排服务。通义、DeepSeek、Kimi、Ollama 才是「脑子」。
2. **大模型只处理文字和工具 JSON，从不直接听 Opus，也不直接发 UART。**
3. **ESP32 工程里搜不到调用大模型的代码。** 板上只做到：PCM → Opus → WebSocket。ASR 和 LLM 在服务器里。

可以把它想成一部戏：ESP32 是耳朵和嘴，服务器是导演，大模型是编剧，ASR/TTS 是字幕组和配音。

---

## 2. 各角色：输入 / 输出

| 角色 | 是什么 | 输入 | 输出 |
| --- | --- | --- | --- |
| ESP32 小智固件 | 麦、喇叭、唤醒、MCP 工具箱、串口开车 | 声波；下行 Opus；`tools/call` | 上行 Opus；执行 `CarSet` |
| 服务器（xiaozhi.me 或自建） | 调度中心，**不是**大模型 | 设备音频和 JSON | 去调 ASR / LLM / TTS；再拆回给板子 |
| ASR | 听写 | 语音（解码后的 PCM 等） | 一句中文，如「往前开」 |
| 大模型 | 只处理符号 | 文本 + 历史 + 工具列表 | 回复文本，和/或「调用某某工具」 |
| TTS | 配音 | 要说出口的字 | Opus 语音 |
| MCP | 设备和云之间的工具协议 | `initialize` / `tools/list` / `tools/call` | 工具清单 JSON；板上跑回调 |
| STM32 | 底盘 | `0x5A` 速度帧 | 电机 /（阿克曼才有）舵机 |

服务器不「思考」。它决定：这段音频交给谁识别、识别完拼什么上下文给模型、模型若要调工具就去问板子、哪些字拿去合成、合成完的音频怎么推回 WebSocket。

## 3. 大模型到底吃什么、吐什么

### 输入（全是文本/结构化，没有波形）

- 系统提示：你是小智，可以控制设备……
- 对话历史
- 本轮用户话（**ASR 已经转好的字**）
- 工具清单（设备 `AddTool` 之后，服务器用 `tools/list` 拉来的）

工具项长这样（示意）：

```json
{
  "name": "self.car.forward",
  "description": "让小车前进",
  "inputSchema": { "type": "object", "properties": {} }
}
```

### 输出（也不是声音）

- 普通回复：「好，我让小车前进。」
- 和/或工具调用：`self.car.forward`，参数 `{}`

两种可以同时有。服务器看到工具调用就走 MCP，看到要说的话就走 TTS。

**谁给模型喂输入？服务器。模型输出先回到服务器，再分流到板子。**

`AddTool` **不会**自己把工具发给模型。它只在 ESP32 内存里登记。连上云后，服务器来问 `tools/list`，固件把登记表打包回传，云端再塞进大模型的 Function Calling。见 [MCP 流程](https://github.com/78/xiaozhi-esp32/blob/main/docs/mcp-protocol.md)。

## 4. 同一条 WebSocket 上的两条管道

```
声音管道（二进制 Opus）
  上行：你的说话 → 服务器 → ASR
  下行：TTS → 喇叭

控制管道（JSON：hello / listen / stt / tts / mcp）
  状态、字幕、工具发现与调用
```

大模型只碰控制管道里的**文字和工具 JSON**。UART 只出现在 MCP 回调里，模型不知道 `0x5A`，也不知道 GPIO8。

---

## 5. 上电后、还没说话

```
ESP32 连 WiFi
  → WebSocket（地址在 NVS，官方服或自建）
  → JSON hello（我会 Opus 16 kHz、我会 MCP）
  → 服务器回 hello，给 session_id

服务器（MCP 客户端）→ 板子（MCP 服务端）：
  initialize
  tools/list
板子把 self.car.forward 等登记项以 JSON 交回
服务器缓存这份列表，之后每次问模型都带上
```

此时模型还没上场，但「能开什么车」已经在导演手里。

`AddTool` 必须在板级 `InitializeTools()` 里、启动时真正被调用，才会出现在 `tools/list` 里。音量、亮度等来自固件 `AddCommonTools()`。

## 6. 你说「往前开一下」：逐步时间线

```
声波
  → ESP32 麦 → PCM → Opus
      → 服务器 → ASR → 「往前开一下」
                    → 拼上下文（历史 + 工具表）
                    → 大模型
                         ├─ 调用 self.car.forward
                         │     → 服务器 MCP tools/call
                         │     → ESP32 回调 → UART → STM32 → 电机
                         └─ 「好，前进了」
                               → TTS → Opus
                               → ESP32 喇叭
```

1. **板上听见。** 本地 WakeNet 只做唤醒（「你好小智」）。唤醒后发 `listen`（start/detect），麦克风约 60 ms 一帧压成 Opus 上传。板子不把「往前开」识别成汉字。
2. **服务器收音频。** VAD 判断说完，交给 ASR。
3. **ASR → 字。** 得到文本。常给板子推 `type: "stt"`，屏幕先出字。
4. **服务器组装给模型的那一包。** 用户文本 + 历史 + 系统提示 + 工具列表 → 通义 / DeepSeek / Ollama。ESP32 不出现在这一跳。
5. **模型思考。** 判断对应 `self.car.forward`，可能同时生成口语。
6a. **动手：** `tools/call` → 板上 `CarSet` → `0x5A` 给 STM32。
6b. **说话：** `tts start` + 下行 Opus + `tts stop` → 解码播放。
7. **一轮结束。** 示例每 200 ms 重复速度帧，直到再说「停」、模型再 `self.car.stop`。

## 7. 从固件代码看：声音如何离开 ESP32

固件头文件写死了两条流（[`audio_service.h`](https://github.com/78/xiaozhi-esp32/blob/main/main/audio/audio_service.h)）：

```
(MIC) → Processors → Encode Queue → Opus Encoder → Send Queue → (Server)
(Server) → Decode Queue → Opus Decoder → Playback Queue → (Speaker)
```

### 7.1 麦：I2S 读成 PCM

[`AudioService::AudioInputTask`](https://github.com/78/xiaozhi-esp32/blob/main/main/audio/audio_service.cc) 循环读麦。唤醒或正在听时，一次约 160 点（10 ms、16 kHz）：

```
ReadAudioData(data, 16000, 160)
  → codec_->InputData()     // 板级 I2S，INMP441 在这
  → 必要时重采样到 16 kHz
```

`ReadAudioData` 用的是 `board.GetAudioCodec()`。读上来的是 `int16` PCM，不是字。

### 7.2 先唤醒，再「开始听」

同一段 PCM 会喂两个模块：

- `wake_word_->Feed(data)` — 本地 WakeNet
- 若已开语音处理：`audio_processor_->Feed(data)`

唤醒成功：[`Application::HandleWakeWordDetectedEvent`](https://github.com/78/xiaozhi-esp32/blob/main/main/application.cc) → `BeginWakeWordInvoke`：

1. `OpenAudioChannel()` 连 WebSocket（[`websocket_protocol.cc`](https://github.com/78/xiaozhi-esp32/blob/main/main/protocols/websocket_protocol.cc) 读 NVS 里的 `url`）
2. 发 JSON `hello`
3. 状态变成 Listening
4. [`StartListeningAudio`](https://github.com/78/xiaozhi-esp32/blob/main/main/application.cc)：
   - `protocol_->SendStartListening(...)` → JSON `type=listen, state=start`（[`protocol.cc`](https://github.com/78/xiaozhi-esp32/blob/main/main/protocols/protocol.cc)）
   - `audio_service_.EnableVoiceProcessing(true)`

### 7.3 PCM 进编码队列

`audio_processor_` 的 `OnOutput` 把处理后的 PCM 推进编码队列。`OpusCodecTask` 里 `esp_opus_enc_process`，得到 Opus，放入 `audio_send_queue_`，并触发 `on_send_queue_available`。

### 7.4 主循环发包

[`Application::Run`](https://github.com/78/xiaozhi-esp32/blob/main/main/application.cc) 等到 `MAIN_EVENT_SEND_AUDIO`：

```
PopPacketFromSendQueue()
protocol_->SendAudio(packet)
```

### 7.5 WebSocket 二进制发出去（固件终点）

[`WebsocketProtocol::SendAudio`](https://github.com/78/xiaozhi-esp32/blob/main/main/protocols/websocket_protocol.cc)：

```
websocket_->Send(..., binary=true)
```

旧版直接发 Opus；v2/v3 前面加头（时间戳、长度）。**没有 prompt，没有 tool 列表。**

固件侧到此结束。仓库里搜不到 `openai`、`DeepSeek`。

| 想看 | 打开 |
| --- | --- |
| 麦怎么读 | `audio_service.cc` → `ReadAudioData` / `AudioInputTask` |
| 何时开始上传 | `application.cc` → `StartListeningAudio` |
| PCM 何时变 Opus | `audio_service.cc` → `OpusCodecTask` / `OnOutput` |
| 谁真正发包 | `application.cc` → `MAIN_EVENT_SEND_AUDIO` |
| 包长什么样 | `websocket_protocol.cc` → `SendAudio` |

## 8. 从服务器代码看：字如何进入大模型

开源后端收音频在 [`receiveAudioHandle.py`](https://github.com/xinnan-tech/xiaozhi-esp32-server/blob/master/main/xiaozhi-server/core/handle/receiveAudioHandle.py)：

```
handleAudioMessage(pcm_frame)
  → VAD：这帧有没有人声
  → conn.asr.receive_audio(...)     # 仍不是 LLM
```

识别出整句后 `startToChat(conn, text)`：

```
handle_user_intent(...)
send_stt_message(...)                 # 给板子推 type:stt
conn.executor.submit(conn.chat, text) # 这里才进大模型
```

`conn.chat` 再拼系统提示、历史、`tools/list` 缓存、本轮 `text`，去调 Ollama / 通义 / DeepSeek。那是 Python（或官方闭源服）里的 HTTP。

官方服第 1–5 步固件相同，第 6 步换成 xiaozhi.me，ESP32 工程里同样看不到模型 API。

## 9. MCP：`AddTool` 怎样让模型「看见」工具

分三层：

1. **板上登记。** `mcp.AddTool("self.car.forward", "让小车前进", ...)` 写入 `McpServer` 内存。此时模型不知道。
2. **云端来拉。** hello 带 `"mcp": true` → `initialize` → `tools/list`。固件把所有 `AddTool` 序列化成 JSON。
3. **喂给模型。** 后台用 Function Calling 把清单和用户话一起发给 LLM。模型输出「调 `self.car.forward`」→ 云端 `tools/call` → 板上 lambda。

听懂「往前开 / 前进 / 开过去」的是大模型泛化，不是板上 `if (话 == "前进")`。description 写清楚，对得上的说法就多。

控制台 [xiaozhi.me](https://xiaozhi.me) 里若能看到 `self.car.forward`，说明 `tools/list` 已成功。

## 10. 和本车 UART 怎么接

小智假装自己是原来的 Nano，往 STM32 USART1 发同样的 12 字节帧（不改底板固件）：

```
5A 0C 01 01  vxH vxL  vyH vyL  wzH wzL  00 FF
```

三个 int16 是车体速度（ROS `cmd_vel`），不是三颗电机：

| 量 | 含义 | 本车 |
| --- | --- | --- |
| $v_x$ | 前进/后退（m/s，帧里 $\times 1000$） | 用 |
| $v_y$ | 左右平移 | 不用，填 0 |
| $\omega_z$ | 绕竖直轴（rad/s，$\times 1000$） | 用：差速靠两轮转速差；阿克曼再换成转角 |

阿克曼固件里大致是：

$$
\theta = \arctan\left(\frac{\omega_z \cdot L}{v_x}\right)
$$

$v_x = 0$ 时除法没意义，轮速也是 0，只打方向、不画圆。画圆和 Nano 时期一样，要 $v_x \neq 0$ 且 $\omega_z \neq 0$，半径大约：

$$
R \approx \frac{v_x}{\omega_z}
$$

示例：`CarSet(250, 0, 350)` 即 $0.25\,\mathrm{m/s}$ 与 $0.35\,\mathrm{rad/s}$。约 800 ms 无新帧会停车，所以每 200 ms 重复发。末字节 `0xFF` 跳过 CRC。

**车上不一定有舵机。** 冰达同一套源码用 `BASE_TYPE` 区分：`BASE_2WD` 两轮差速无舵机；`BASE_ACKERMAN` 才有 PB9 舵机。以实物前轮为准。差速车 `v_x=0,\omega_z\neq 0` 可以原地转；阿克曼不行。

接线（DevKitC-1 排针没有 GPIO17/18，用 GPIO8/9）：

- TX GPIO8 → 40 针脚 8；RX GPIO9 → 脚 10（可先不接）；GND → 脚 6
- 不要接脚 2/4 的 5V；整套 Nano 拔掉；必须共地
- 小智先用 Type-C 独立供电

麦/功放/OLED 占用：4/5/6、7/15/16、41/42，UART 不要抢。

## 11. 换模型、自建，和「小模型」

- 小智 ≠ 7B 小模型。板上离线的只有唤醒词。对话 LLM 在云端或你电脑上。
- 官方控制台可换通义、DeepSeek 等；固件和 MCP 不用改。
- 整条链自建：固件仍是 xiaozhi-esp32，后端用 `xiaozhi-esp32-server`，LLM 可接 Ollama。小模型必须会 **tools**，太小或不会 function call 会聊得动、开不了车。
- 建议顺序：官方服先把语音 + MCP + UART 跑通，再改服务器地址接自建。

## 12. 对照时容易混的点

| 误解 | 实际 |
| --- | --- |
| 小智是一个小 LLM | 小智是固件 + 编排；LLM 可大可小，在服务器后 |
| `AddTool` 直接通知模型 | 只登记；云端 `tools/list` 才上报 |
| ESP32 把语音送给 DeepSeek | ESP32 只送 Opus；服务器 ASR 后再调模型 |
| 三个速度 = 三个电机 | 车体 $v_x,v_y,\omega_z$ |
| 画圆必须有舵机 | 差速也能 $v_x+\omega_z$ 走圆弧 |
